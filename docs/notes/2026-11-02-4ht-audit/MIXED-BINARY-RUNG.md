# First mixed-binary ladder amendment

Status: proposal for bennett-4ht; not a published contract, implemented test, or present rung acceptance claim.

Filing trigger: when **rung 3 or rung 4 lands**, whichever happens first, the orchestrator files F30 from [cross-repo-beads.md](cross-repo-beads.md) in bennett-conformance with label `fat-object`. Record the landing evidence and parent bennett-4ht. This is an additive rung, provisionally **3M**; do not renumber or change the acceptance of rungs 1–8. The trigger means create the durable work item, not demand that mixed execution already works when rung 3/4 passes. Implementation can wait for the published boundary contracts and is not on the current critical path.

Use the [shared scope](../2026-11-02-rev2/fat-object-scope.md) and [audit F01–F31](AUDIT.md) as the boundary inventory. The first fixture is deliberately small evidence of the native/device split. It does not discharge general native memory sharing, pointer-rich state, persistent quantum handles, arbitrary native layouts, or brownfield application coverage.

## Proposed ladder row

| Rung | Demonstration | Acceptance |
|---|---|---|
| 3M | Ordinary native host with two marked device modules | A C program retains its ordinary native main, process argv/envp, host-only libc and a native-only object-library dependency. Two marked modules and their reachable device closures are embedded as ISA payloads in the same fat object as the native host. The production native host executes both marked entries and returns through their real launch stubs. Every declared input gives the independent native result and zero device faults. Each embedded program/root is bound to its actual object, linked closure, certificate, layout, budget and invocation; native-only symbols require no ISA region/frame/certificate records. Both executors produce the same declared results; eligible device runs reverse to their own entry state and replay deterministically, with native host events outside that reversal. Association, ownership and replay corruption controls fail before an unrelated device effect can occur. |

## First fixture and domain

Keep main, a host-only formatting/probe library, and two marked modules in separate translation units. The probe library is an ordinary native object with **no bitcode**, calls host libc, and updates a host-only counter. Main reads one command-line byte and a named environment value, calls the native probe before, between and after the marked calls, and checks the counter. The build must not request whole-program reversible mode. An H function containing no marker remains native even when a marked module is also linked.

Each marked entry is a CC launch entry wrapping a small R function, using the published marker route. The R body has dialect §7.6's `void(ptr env)` signature; its environment is device CC memory prepared by the wrapper from scalar launch arguments, and the wrapper marshals the scalar result back. No ordinary host pointer is passed in this first fixture. Module A's entry returns `(x + 1) mod 256` and its R body writes a fixed tagged byte sequence to its **R console model**. Module B's entry returns `x XOR 0x5a` and has no model effects. Main calls A, then B with A's result, then A again. The repeated call exposes accidental per-entry reinitialisation, wrong root selection and shared process-global tape cursors. All arithmetic is explicitly unsigned and defined. State the F31 boundary-preservation construction and test a small wrapper that could otherwise inline into native main.

Use two independently selectable embedded ISA programs, each fully linked against its required device closure. They may share content-addressed library definitions; certificate/invocation roots remain distinct. This first fixture shares no live quantum resource or pointer between those programs, so it does not invent cross-ledger handle transfer. If packaging stores several modules within a single linked payload, add a second independent payload/root so that at least two independent root bindings are exercised.

Enumerate x = 0..255, two argv/envp context cases and two modes (0 and 1) for the host-only probe: each probe call adds `1 + mode` to its native counter, so three calls yield `3 * (1 + mode)`. The context cases use an ordinary argument/environment string and an empty extra argument/environment string respectively; pin all bytes and terminators in fixture data. Pass the context case as explicit input to the host baseline and mixed executable. Device functions take scalar arguments only; no implicit `main(argc,argv,envp)` or `bennett.argv` request is part of either marked function. A device process-context service belongs only to a separately requested entry profile.

The R helper bodies may be compiled natively in independent baseline/comparison builds, where the fixed console event is represented by a declared deterministic comparison backend. No test-runtime marker definitions may enter the production mixed executable. Host-only library source and behavior are identical between the independent host baseline and the production host. A fixture-specific native baseline adapter is recorded and hashed; it is not a fallback implementation selected when production lowering fails.

## Required evidence rows

1. **Frozen inputs and real production build.** Record source hashes, stock frontends/LLVM majors, plugin/driver/VM/reference binaries and versions, runtime/arith publications, target, layout, flags and exact commands. Use applicable major pairs from the published envelope. Pin immutable inputs and bound every command's time, worker count and memory. No analysis-only/reference-only or diagnostic artifact satisfies a production row.
2. **Native host retained.** Link and execute the actual generated host module plus its native-only object, native libc, production launch runtime and embedded ISA payloads. Verify native main and probe remain native definitions; the probe has no bitcode/device variant; no source marker operation survives in native code. Execute the counter, argv/envp and host-output checks. Mere existence of host.bc, a native mock launch runtime, or direct `run-program` calls cannot pass this row. Record the container/executable digest and embedded payload extraction/inventory evidence.
3. **Exact inventory and device closure.** Admit/hash every extracted linked ISA payload with each executor. Validate the selected ABI entry, object identity, linked root/closure, certificate/build/layout associations and required versions against the published mixed profile. Inventory every required device region/owner/link record and every device-reachable runtime helper; verify native main, probe, host argv/envp setup and host-only libc are absent from that ISA inventory. Reused static closures retain each root's own binding/context `[]`. CC/R functions are not assigned fictitious quantum-region records merely to fill an inventory.
4. **Two independent comparisons.** The ordinary native host baseline checks full process outputs, status and host counter. Separately, the materialised-device comparison checks each selected device closure with the same classical input, tuple, layout and declared device-model inputs, using the published runtime/arith and classifiers. Keep its no-host-libc and fixed-layout requirements. The production host can use its own libc and supported layout. Record defined/undefined/layout-dependent fractions and actual classifier coverage; the small fixture's declared domain must have zero exclusions and faults. If an infrastructure failure prevents comparison, report it explicitly, not as native equality.
5. **Native launch path on both executors.** Select VM and reference through a published adapter/runtime edge and execute the same production native host for each. All x/context/probe cases must call the intended A/B/A roots, return exact scalar values, preserve native state and show zero faults. For each invocation record the program instance, root, resolved arguments, budget tuple, status, close and model outputs. A subprocess integration is acceptable only if it implements the published production adapter and its ownership/reverse protocol; calling an executor CLI directly as the fixture's entire program is not mixed execution.
6. **Budgets and failure.** Give each device invocation its explicit tuple under the published R accounting; keep native host/probe cost separate. Add one insufficient-device-budget case that produces the specified terminal fault and preserves its reversible prefix. Do not count it among successful domain cases. Ensure the stub propagates that fault without returning a fabricated scalar success and without terminating unrelated native work except as the declared host API specifies. Equal tuples do not identify tokens or certify another root.
7. **Per-run reversal and lifetime.** Through the production runtime's test/control interface, retain each run until the eligible completed or failed run has been reversed and checked, then close it before reusing owned state. Compare full device state within each executor: memory/allocator metadata, models, applicable register/token state and active history. Verify a later A call sees exactly the intended program state. Native main/probe events already observed are neither undone nor re-issued. Digests are compared only within one executor. If the runtime normally closes immediately, the adapter must explicitly support a retained-run test mode; a second independent function call is not reversal.
8. **Effect tape and replay.** Bind each A run's R tape, entropy and any allowed host replies to the correct program/root/invocation and replay-profile version. B has no model effects. Keep ordinary host stdout and probe events outside device tapes and identify their ordering in boundary evidence. Feed the saved device journal into replay and require the exact recorded effects/results; include a corrupted effect byte and a tape from the wrong A invocation/root as negative controls. Replay must not issue native events again. A fresh run that ignores the supplied journal fails this row.
9. **Negative association and ownership controls.** Substitute the other object's digest/root/certificate association, remove a reachable device helper, use an incompatible launch signature, and provide a stale/wrong-owner run token or opaque launch id through the adapter's control interface. Each control must receive a specific admission/binding/state diagnostic before the unrelated root executes or any forbidden effect occurs. Record the preserved pre-error state. Do not require a register allocation in this scalar fixture solely to manufacture an id test; register-specific controls join the persistent-resource extension below.

These are required rows for 3M once implemented, with independent statuses and failure propagation. Missing publication/implementation dependencies remain explicitly unimplemented/blocked, never `PASS`, expected failure, a diagnostic substitute or a reason to shrink the promised mixed capability. No part of 3M substitutes for rung 3's musl closure or rung 4's real SQLite, full oracle domain, Grover and estimate checks.

## Boundary prerequisites and later extensions

| Obligation | Before first 3M execution | Explicit later acceptance extension |
|---|---|---|
| Container/root/certificate and launch lifetime | Publish F01/F03/F04/F06/F07/F21 associations and scalar call/return profile; adapt consumers against it. | Libraries with shared device imports and more native/LLVM/front-end combinations. |
| Native entry/argv/envp/libc | Scope F10/F12/F17/F20/F26–F29 and preserve the F31 optimisation boundary so the scalar mixed host is admitted while existing whole-device modes remain available. | Real brownfield libraries and process contexts; no host-only-libc closure requirement. |
| Host memory by reference | Record F08/F11/F14/F15/F16/F18/F23 as still open. Scalar-only coverage is labelled as such. | Add native malloc/stack/global ranges, pointer-free bytes and a pointer-rich graph with aliases/cycles; host mutation between calls; input/private-copy and permitted writeback; liveness, range, ownership, allocator history and reversal/interference checks. Native main must remain native; promotion-only execution cannot pass this extension. |
| Persistent handles/resources | Preserve F06/F13/F24 rules; first fixture leaves device handles inside device/runtime boundaries. | Return/transport opaque launch ids across calls in the same owning program, wrong owner/stale/measurement/free/unload and overlapping-run checks; keep source handle operations and measurement-dependent device control out of native code. If resources cross separately loaded programs, publish a transfer/shared-ledger protocol first. |
| General layout and replay | Use one explicitly supported mixed layout and replay profile, preserving address semantics. | Other ordinary native layouts, pointer/function identity mappings and multi-run boundary ordering; no universal fixed-address or process-global tape assumption. |

The orchestrator should retain these extensions as separate acceptance obligations under bennett-4ht. Passing 3M proves the declared scalar split and its lifecycle only. It must not be described as completion of host-memory-by-reference or the entire north-star fat-object experience.
