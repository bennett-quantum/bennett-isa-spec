# Mixed fat-object lock-out audit

Design audit for **bennett-4ht obligations 1–2**. No implementation or published contract is changed here. Build on the [shared scope](../2026-11-02-rev2/fat-object-scope.md); that statement remains the common definition. The [08:45Z maintainer ruling][ruling] supplies the architectural constraint from [North Star §2][north-architecture], [§3.3][north-compilation] and [§4.4][north-ownership]. In particular, “whole-program” analysis must not become a requirement that the device object contain the whole native binary.

The significant lock-outs are the missing ordinary-pointer launch/memory contract (F04/F08/F23), mandatory transitive promotion of pointer-sharing host code (F14), and the unqualified inventory of every link global (F11). The remaining rows distinguish missing associations and missing tests from compatible device-only restrictions. Current ladder success would not establish mixed-binary execution: the gates inspect host bitcode but drive device objects directly.

## Evidence and severity

This is a read-only source audit of ISA 0.9, published dialect 0.2.12 and the 0.3 draft, the ladder's README/design/gate scripts, VM source interfaces and plugin documentation. The ladder and plugin still name older pinned contracts; their behavior is audited as written, without claiming that a 0.9 publication upgraded those consumers. No interpreter, build, corpus or full gate was run. VM findings are source observations, not reproduced runtime failures. Driver and runtimes obligations below derive from the published interfaces; their implementations were **not** inspected.

Locations below are file links with clause names and source line ranges. [sources.json](sources.json) records source SHA-256 values and the actual cited excerpts, since sibling worktrees are changing concurrently; line numbers describe that snapshot. [verify_audit.py](verify_audit.py) checks document structure, all 31 proposed beads, links and cited excerpts. It does not establish execution conformance.

- **locks out**: the present rule/interface cannot express the named mixed case. This identifies an exact amendment, not permission to reject the source program or discard the capability.
- **makes harder**: composition remains possible, but an association, integration interface or regression is missing. Absence of an end-to-end demonstration is not itself an architectural impossibility.
- **neutral**: a legitimate device-closure or explicit whole-device-mode rule. Preserve it and state its boundary; applying it to all native code would create a lock-out.

“Cheap now” prices the text/design decision or focused regression specification. It never claims that a native launch shim, shared-memory runtime, or full mixed rung is cheap to implement. Every row has one corresponding proposed bead in [cross-repo-beads.md](cross-repo-beads.md); neutral rows request a boundary clarification or preservation check, not removal of an invariant.

## ISA spec

F01–F09 leave the inner ISA closed and independently verifiable. Native container fields belong to a separate versioned envelope, not ad hoc fields that current §9.1 must reject. Two embedded objects need not be flattened into one conflicting layout. If they actually import each other, §9.3 resolution, whole device-closure validation and certificate rebinding still apply.

The certificate change is a scope statement plus an association, not a demand to create region records for native functions or every CC/R function. All records that the selected device closure actually requires remain mandatory. Separate device roots can reuse static callee code while retaining distinct invocation bindings and root-relative contexts. [Current §11 action-support text][isa-support] already states the desired native/device boundary for `$construct`/`$release`; generalise that good example to §§9/12/13 rather than claiming the entire published spec excludes fat objects.

The real missing capability is native-memory binding. §10 copies argument buffers, while §7 describes device-address memory. Neither establishes a valid live host pointer. Reversal must also specify when host-visible writes commit, how the host excludes interference, and which version is restored. Those mechanics cannot be replaced by “promote main” while claiming to retain an ordinary host.

## Dialect spec

F10–F20 and F31 apply to both the published 0.2.12 text and the 0.3 draft; the latter changes handle/budget/R realization, not the existence of a native-container ABI. Amend a future version through the contract process; do not silently rewrite the published compatibility unit. In 0.3, “no blocker is active on ISA 0.9” ([§25.1][d3-blockers]) retires named device lowering blockers. It is not evidence that native pointer sharing or mixed packaging is already specified.

Whole-program LTO, polyvariant cloning and complete device closure are compatible with selective lowering. The problem is universalising “every global of the link,” transitive promotion, and whole-device main startup. Likewise, “handles never in host native code” protects source-level device operations. Existing opaque launch-id transport does not allow native dereference, arithmetic on handle identity, gate execution, or moving measurement-dependent device control to H. The first mixed fixture can leave all such values inside device/runtime boundaries; later persistence tests must preserve those rules.

Device libc closure and the materialised native comparator must remain strict. A host-only libc or native library does not need an ISA record. Sharing a source function between H and L still requires a device version and shared-state semantics; labelling a callee “host-only” cannot hide a device-reachable call.

F31 is an inference about the interaction of post-link optimisation and function-granularity tier assignment, not a reproduced inliner bug. Source module boundaries alone do not promise that a small marked wrapper survives LTO. The mixed profile must state a supported boundary-preservation or re-outlining construction rather than relying on that accident.

## VM

F22–F24 follow from executable interface bodies, not the launch module's stale “0.8” header comment. The current program object owns one device Object and Resources; the loader takes UTF-8 ISA text. This is suitable as an inner loader beneath a fat-object adapter. Its per-program locks and per-run journals are useful boundaries to retain.

The C argument matcher has no ordinary-pointer binding, and the sparse device memory backend is not native host memory. `--mem global=hex` and CLI integer-pointer values do not remedy that. Add memory and container routing only against published contracts. No claim is made that running the VM CLI today launches a native host or that saved-array replay validates container identity.

## Plugin

F25 preserves the plan's H-original/device-clone split. Documentation contains older milestone and fixture descriptions; [the Resume block][plugin-resume] reports later work, so an old “unimplemented” sentence is not treated as a reproduced current production failure. The audit uses those documents to identify the interface obligations still needing mixed acceptance, without reading or modifying plugin implementation.

The key regression will combine native-only work and a real marked module, verify that only the latter's reachable device closure appears in ISA objects, then execute the generated host stub. Scalar reference objects and a native mock protocol do not establish that integration.

## Driver and runtimes (contract consumers)

F21 is a driver publication task inferred from dialect §19.9 and North Star §4.4, not a source-level driver defect. ISA owns the exchanged format; the driver owns producing/consuming it. Container layout, shim ABI, root selection, versions and lifetime rules must be published before cross-repo implementation, rather than copied from another repository's source or inferred from `out/main` filenames.

Runtime implementation follow-ups belong under the F08/F12/F17/F18 contracts: native startup/libc belongs to native main, device process context only to a requested whole-device mode, and R/L effect models remain distinct from host I/O. No new runtime implementation bead is proposed independently of those decisions; the orchestrator should attach owning implementation work when the versioned contract is accepted.

## Conformance ladder

F26–F30 identify a coverage gap, not a reason to weaken existing acceptance.
