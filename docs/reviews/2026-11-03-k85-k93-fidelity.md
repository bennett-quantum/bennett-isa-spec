**D-K91-1 (meaning; b-isa-spec-b3ui).**

- **Accepted** (doc.md:128–131, 185–186): "Publish the extension under an explicit launch/sched ABI revision or feature contract, including loader capability negotiation"; "ABI revision must allow old callers/libraries to negotiate support explicitly."
- **Applied** (§10.1, 2600–2606): the editor directive is copied in as normative text, followed by: "The additive symbols and binding rules above define the launch/sched 0.9 feature `token_aliases/1`. Loader capability negotiation establishes support for both additive symbols and the token_aliases metadata contract before issuing an alias-aware request; symbol availability alone does not authorize silently dropping the partition."
- **Why it matters:** §10 and §11 define no negotiation mechanism. There is no query symbol, feature list or version field; only the pre-existing BENNETT_E_VERSION exists. Specifying the mechanism is new ABI text, so it needs the note author and the council.
