# Adversarial review: reference interpreter ISA 0.9 migration

Date: 2026-11-01 22:28 UTC. Reviewer: opus-ref09-review (took over from a Muse predecessor whose progress file held no findings).
Pinned tree: `c1d1320`, by `git archive` under `.tmp/ref09-review/pin-c1d1320`. Baseline for 0.8: `8e481ce`.
Later commit `fb4aa11` adds `source_constructor.rs` and touches none of `identity.rs`, `object.rs`, `certificate.rs`,
`metadata_schema.rs` or `claims.rs`, so every defect below still applies there. No source or spec was edited.
Probes: `.tmp/ref09-review/probes/` (`p1.py` to `p12.py`, `diff08.py`, `extract.py`).

## Verdict

The K5/K6 typed-fault work holds up under attack, and 0.8 is unchanged on every observable I compared. The migration is
not correct on identity: **the reference computes wrong hashes for ISA 0.9 objects that have a layout section**, so it
rejects published §16.3 vectors. The migration's tests hid this by rehashing with the interpreter's own identity.

## Attacked and held

- **0.8 byte-for-byte.** `diff08.py` compared rc, stdout and stderr between `8e481ce` and `c1d1320` over 615 runs on all 0.8
  corpus objects: `check`, `hash`, `run-cc`, `run-program` with and without `--reverse`, `reverse`, `run-oracle`, `run-action`.
  No differences. Six deliberately invalid headers and ABI strings still reject with the same rc but different diagnostic text
  (for example `expected object=0.8` became `mixed object versions: expected object=0.8`); no bead.
- **Version gating, 0.8 side.** CC `fault` rejects; `--reverse` of a FAILED run keeps its diagnostic; nested `abi`, certificate
  `versions` and device versions of 0.9 reject, closing the shared `version` enum widening.
- **K5 codes.** 0 maps to 4; 1, 2, 3, 2^64-1 exact, 2^64 rejected at admission. Implicit causes: div0 and overflow via the
  migration's tests; load, free, alloc heap, alloc table, effect range including partial and block, hostcall range, unknown
  device 8, entropy 10, use-before-definition, illegal uncall, dirty `qreg.free`, use after free.
- **K5/K6 terminal and reversal.** One record, no results, FAILED reverses to entry state (`equals_entry` true) after console,
  clock, entropy, block write and read, CC hostcall with reply, action call, live qreg and view, and replayed tape.
  Measure then fault gives `E_NOT_REVERSIBLE`. Host fuel stays a host error, not fault 1.
- **Q fault path.** `fault 0` and `lift.faultif x 0` give 4, `step-check --exhaustive` passes, literals above F reject, including
  in an lproc under its oracle.
- **K10.** 511 and 513 byte images reject at initialisation; 0, 512, 1024 pass.
- **K79 admission on 0.9.** `()` at A=0 admits; nonempty at A=0 and empty at A>0 reject, for all four rows.
- **K79-K81 locks.** `git diff 4d1a1c2^ c1d1320` changes no fixture or catalog bytes and no expected bytes in those tests; it
  only routes expansion through the checked published catalog. `tests/parser.rs` changed its unsupported-version sample from 0.9
  to 1.0, which is necessary.
- **K16 frame expressions.** Wrong arity, division by zero, negative, fractional and overflowing widths all give clean errors.

## Plausible, not confirmed

- `qreg.new any 1000000000000` ends rc=1 with a host-limit error rather than FAILED with code 2. §4.9 maps an unsatisfiable
  `qreg.new` to 2, and §17 item 16's default also gives 2, but that item leaves the point executor-defined and untested.
- `subject.closure_hash` naming an unlinked closure passes `check`. `verify_certificate` stopped first on the legacy table read,
  so its behaviour is unobserved.
- `Cargo.toml` moves `bennett-isa-conformance` from dev to normal dependency, so reference and conformance now share one
  expander. Conformance is less independent as a check on expansion; no wrong output observed.
- A table with too few rows passes `check` (replay rejects it), and K13 row-completeness may be intended for admission.
- My E17.10 and E17.11 witnesses were malformed and hit unrelated errors, so those items are unconcluded.
